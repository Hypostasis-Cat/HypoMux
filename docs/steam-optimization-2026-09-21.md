# Steam 下载优选：功能与界面完善

## 核心行为

- HTTP 内容候选改为每项发现任务最多两个校验工作线程。健康候选校验完成即进入候选池，不必等待前面的慢节点超时；每网卡最多八个候选、全局探测字节预算和发现任务上限保持不变。两个发现任务同时运行时最多四个内容校验请求。
- 原节点已有至少三个新鲜有效样本、没有优先节点且没有并行试用时，允许未试用的已验证候选提前获得一条试用连接。仍保留普通的 1/8 探索节奏、每候选一条试用和每网卡/域名最多两条试用；提前试用不等于提前晋升。
- 出现优先节点后，每八次选择保留一次原路连接，持续采集对照样本。优先资格仍要求同网卡、同域名、相近负载、新鲜有效样本以及连续两个窗口超过 15% 的优势。
- 原节点变化时清除旧对照产生的优先资格和连续优势计数。
- 十秒以上没有有效样本、候选建连失败或传输失败后，清除旧评分和负载样本，保留内容验证及流量归因。恢复时重新学习，防止暂停前的高吞吐污染新一轮评分。
- 原有严重低速退出继续保留。新增中度退化保护：至少 8 MiB 有效样本、可比较的新鲜原路基准、连续四个窗口且持续至少十五秒低于原路 75% 时，候选冷却一分钟。客户端背压、请求间隔和无对照样本不作为退化证据。不终止已有下载连接。
- HTTP 候选池达到容量上限时，已有条目仍可重新验证；仅禁止新增条目。

## 页面与操作

- 明确区分关闭、等待引擎、核心不兼容、等待下载、验证、学习和已有优先节点；桌面服务新增可选 `runtime_state`，兼容旧核心。
- 展示最近五秒总吞吐及切换吞吐，累计流量自动选择 B/KiB/MiB/GiB；将含糊的“已传输数据”修正为“已传输连接”。这些指标不是净提速百分比。
- 节点可按 IP/域名/网卡搜索，并按网卡、活跃状态、优先资格和暂不可用状态筛选。每个节点可展开有效样本、归因流量和失败数。
- 补齐空列表引导、手动刷新、错误重试、缓存数据标识、更新时间、Core 版本/提交号/运行模式和空诊断说明。
- 明确重新评估会清空本轮节点学习及统计，并显示结果反馈；旧轮询结果不会覆盖重新评估后的状态。
- 沿用主题变量与 Fluent 控件，支持中英文、键盘操作和节点表格内部滚动。

## 验证

- 引擎 `go test ./... -timeout 90s` 通过。
- 桌面后端 `go test ./internal/services -count=1` 通过。
- 引擎代理/服务端与桌面服务 `go vet` 通过。
- 前端 TypeScript 检查通过；33 个测试文件、166 项测试通过。
- 新增测试覆盖提前试用及并发限制、保留原路对照、暂停/失败清除旧评分、持续退化和正常波动区分、慢校验不会阻塞健康节点，以及前端筛选/刷新失败/重评估竞态。
- 浏览器使用模拟数据检查明暗主题、中英文、1120×800 与 960×720 布局和搜索操作；模拟数据未接入生产入口。

## 实际效果验收

本轮验证了决策行为与协议回归，没有执行真实 Steam 下载，也没有测得净提速百分比。正式效果需使用同一下载任务做关闭→开启→关闭的稳定窗口对照，记录平均吞吐、磁盘活动、候选切换及失败。不同运营商、纯 IPv6/NAT64、HTTPS 的实际效果仍需实机验证。

没有扩大可替换域名范围、引入社区 IP 表、跨域复用签名或解密 HTTPS。无可用候选时仍正常沿用原路。
