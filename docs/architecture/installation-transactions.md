# HypoMux 安装、更新与恢复方案

## 目标与兼容约束

保留 NSIS 界面、安装包格式、`HypoMux_Setup_<version>.exe` 命名、更新 manifest 格式、
Ed25519/Authenticode 验证、正式/预览渠道及卸载身份。旧客户端可下载并运行新版安装包；
旧客户端自身启动器损坏时，支持手动覆盖安装。用户配置目录不参与替换或删除。

在现有桌面程序中提供独立命令入口，在初始化界面、WebView2 和普通启动降权之前执行。
安装器从安装包解压该签名程序作为原生辅助程序，不新增依赖 PowerShell 的安装事务实现，
也不引入一个需要单独配置签名策略的发布二进制。

## 事务顺序

1. 平台检查，解压辅助程序；在受保护的事务目录中恢复此前未完成的事务。
2. 读取恢复后的注册项、选择目录、检查依赖；拒绝未知日志版本、损坏日志或目录链接。
3. 解压完整新载荷，校验文件、记录摘要，将载荷及旧文件备份放入事务目录。
4. 持久化服务配置、安装注册项和 Core 策略快照；事务进入 prepared。
5. 关闭旧 UI、停止旧 Core、恢复软件拥有的网络状态；任一步失败进入恢复。
6. 事务进入 applying；替换桌面与受保护 Core 文件，设置受保护目录权限。
7. 安装并启动 Core，等待服务就绪；写入卸载器、注册项和快捷方式。
8. 验证载荷与服务，事务进入 committed；旧备份可清理。

事务日志原子写入并同步。prepared/applying 状态均可恢复，恢复可重复执行；
回滚失败时保留备份与日志，不开始下一轮安装。无法恢复的原始环境错误必须明确报告，
不能承诺磁盘损坏或管理员手动破坏后的无条件恢复。

## 迁移

识别当前 Wails 注册项、旧重复目录注册项及 Python/Inno 注册项。
新版本成功前不运行破坏性的旧卸载器，不递归删除用户指定目录。
旧 Python 附属文件可以保留，避免误删无法准确归属的数据；成功后移除过时卸载入口。
新旧目录不同时保留旧载荷直至提交，之后只清理明确属于 HypoMux 的文件。

## 更新启动

使用原生辅助进程等待当前应用退出，再通过 Windows API 启动安装包。
启动前再次校验安装包；失败、取消或等待超时保留安装包和结果日志。
不用 CMD 拼接路径，不把“辅助进程创建成功”当作“安装已经完成”。
同一后台服务不允许并发下载或重复启动安装，UI 状态变化不能绕过此限制。

## 验收

- 首次安装、Wails 覆盖升级、不同目录迁移、旧 Python 布局；配置保持不变。
- 中文/空格路径、只读文件、真实锁定、损坏载荷、依赖失败。
- 每个替换步骤注入失败、事务中断重启、回滚中断后重试。
- 服务原本不存在/停止/运行/禁用；恢复配置准确，失败日志可定位。
- 更新取消、退出等待超时、安装失败、签名失败、并发请求。
- 原有安装回归、更新与签名测试、完整 NSIS 编译、代码复查。

涉及真实提权、旧版本真实安装、断电及服务端口的系统验收必须在隔离 Windows 环境执行；
本机不通过真实卸载/服务改动来模拟用户故障。记录自动测试与尚未运行的系统验收边界。

## 实现入口与诊断

- `desktop/internal/setup`：备份、摘要校验、文件属性/ACL、服务配置与恢复动作、卸载注册项及 Core 策略恢复。
- `desktop/build/windows/nsis/project.nsi`：依赖门槛、事务调度、健康检查、提交及中断回调。
- `desktop/internal/services/updater_windows.go`：复制已签名桌面程序作为助手、原子就绪确认、进程句柄等待、原生提权启动及结果处理。
- `desktop/main.go`：在 GUI / WebView 初始化前分派 `--setup-transaction`、`--run-update`、`--webview-check`。
- 构建流水线在桌面程序打包后运行真实二进制的无界面入口测试，防止辅助参数意外启动普通 GUI。

机器安装报告位于 `%ProgramData%\HypoMux\SetupTransaction`，用户安装位于
`%LocalAppData%\HypoMux\SetupTransaction`。`setup.log` 为 UTF-8；`installer-errors.log`
为 UTF-16LE；`journal.json` 记录恢复状态。诊断收集器只读取这些文本，不拷贝备份载荷。
更新报告位于对应 `%TEMP%\HypoMuxUpdate-*\update-result.log`。失败保留安装包；成功只删除安装包，
仍在执行的助手副本及报告留在临时目录，由后续临时文件清理回收。

恢复服务配置不等于自动恢复用户之前的活动代理/TUN 会话；用户配置文件保持原位。
服务无法停止、文件持续被外部程序占用或备份损坏时，保留恢复材料并报告，不宣称恢复成功。
旧客户端中已经存在的 CMD 启动缺陷不能由尚未安装的新版本修复；首次迁移可手动运行新版完整安装包。
