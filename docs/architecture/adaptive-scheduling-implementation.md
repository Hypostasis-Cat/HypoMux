# 最大速度优先：调度升级实施方案

日期：2026-09-21。状态：目标设计及首个实验实现，尚未验证多网卡提速。本文细化 `adaptive-maximum-speed-scheduling.md`。默认仍为旧策略，新增实验选项。

## 双卡退化修正：有界份额自适应（当前实现）

用户明确要求只修复新增自适应策略，原“最大速度优先”轮询保持原行为。临时的永久轮询保护已替换为独立的有界份额控制器 `adaptive_allocation.go`；原轮询选卡代码未改动。

- 冷启动至少 15 秒均匀分配。每张候选卡在窗口内至少有两条传输超过 64 KiB 的连接才允许学习份额；正在拨号、空闲 keep-alive 和明显客户端背压不作为充分需求。已结束连接的窗口剩余字节仍计入速率，持续至少 200 ms 且传输了 64 KiB 才计入结束传输数。
- 在连续五个有效采样窗口中，至少发生 `max(4, 候选卡数)` 次自然选卡，才允许更新比例。没有连接更替时，不把旧长连接的速度变化当成新分配的效果。
- 目标份额为 `0.5 / 候选卡数 + 0.5 × 该卡持续观测速率 / 所有候选卡观测速率之和`；使用平滑加权轮转，而非每个连接都选当前得分最高者。双卡目标限制在 25%–75%，不会因一个短时低速样本变成 0%–100%。这是稳态连接数份额，不保证字节份额。
- 每次有效窗口最多改变 5 个百分点，差别不足 2 个百分点时不追逐噪声；更新时保留分配欠额，避免重复重置轮转使低份额卡饥饿。
- 五窗口平均总吞吐较参考值下降超过 10%，且窗口内确有足够新连接时，回到均匀分配并冷却 30 秒。参考值平滑更新。这个判定是保守的退化保护，不能排除服务器或应用需求改变，也不证明下降是调度造成的。
- 需求不足时均匀分配，不按最少活跃连接覆盖轮询。候选集合变化重新预热，策略切换重置控制器。UDP、显式网卡路由、健康候选及旧轮询保持原语义。
- 遥测状态为 warming-up / balanced / insufficient-demand / adapting / throughput-guard；公开各卡 allocation_share 与实际 effective_tcp_strategy，均匀阶段明确报告 round-robin。

独立下载模型使用链路容量、每条连接的源端限速及固定块大小计算实际交付字节，不把调度器预测当作速度结果。包括启动慢后恢复的长连接、对称分块、非对称分块；同时保留旧 rate/load 策略作为回归对照。该模型不是 WeGame 仿真，不代表真实网络验收；目前仍未复测用户的 WeGame 双网卡环境。

### 当前修正的验证结果

- 代理、API、Server 的回归及 Go race 检测通过；包含八卡最低份额、旧轮询/手动权重不受自适应模型影响、吞吐下降冷却和自然连接不足时不调参。
- TypeScript 检查、17 项首页测试、前端生产构建通过。
- 独立模型的后 150 秒交付量：启动慢后恢复的长连接场景，轮询 10,500 MB、旧评分 7,650 MB、新版 10,500 MB；对称分块两者都是 10,240 MB；60/10 非对称分块轮询 2,741.43 MB、新版 2,997.34 MB。旧评分在非对称模型为 10,401.14 MB，说明当前保守份额策略仍明显限制了异构链路利用，不能据此宣称全面优于旧评分或达到最优。
- 回归对照使用旧评分及冷启动选择逻辑，未包含旧周期探索；用于复现的启动长连接场景只有 16 次选择，不会触发第 20 次探索。模型参数和断言在 adaptive_allocation_test.go 中可复现。
- 尚未完成真实 WeGame 对照；不得将模拟收益换算为用户网络提速百分比。

## 实测退化后的临时保护（历史记录，已由上面的有界自适应替代）

用户在 WeGame 双网卡下载中反馈：轮询可达到约 60–70（未确认单位），自适应时一张卡几乎无流量，另一张速度波动。此前正确性测试不构成吞吐收益验证。

已暂停 `rate / (load + 1)` 评分、最少负载回退和周期探索对选卡的覆盖。它们使用受业务需求和既有分配影响的观测，不能确认新增连接的收益。已保存 `adaptive-throughput` 的配置继续有效，但实际 TCP/UDP 选择使用原轮询。性能采样仅作观测，任何样本状态均不改变轮询序列。

遥测保留请求策略 `strategy=adaptive-throughput`，新增 `effective_tcp_strategy=round-robin`，状态为 `round-robin-protection`；界面说明当前处于轮询保护。该修复是退化止损，不是已经完成了新自适应模型，也不宣称自动检测出了带宽上限。已有 TCP 不迁移，重新测试需要新建下载连接。

回归测试比较两种策略的逐次实际选择，覆盖冷启动、100:1 的观测速率偏差、过期数据、不均衡既有负载和受限候选，包含超过原探索周期的连接序列。恢复自适应覆盖前，必须增加独立业务需求模型和 WeGame 双网卡实际对照；不能仅调整评分常数后重新开启。

## 初版实验实现（历史记录，评分已由上述保护修复停用）

以下章节描述目标方案；当前代码有意采用更小的可验证基线，并未实现全部目标模型：

- 已实现显式策略、新旧配置兼容、Core 支持声明、桌面选择与持久化、启动及热更新回滚、实际策略遥测。
- TCP 选择和拨号预留原子执行；成功连接持有 lease，失败/取消/关闭幂等释放；半关闭不释放。Steam 替换连接在同一网卡登记新 lease，再关闭旧 lease。
- 以完整网卡绑定作为身份；池配置移除绑定后退休旧模型，旧 lease 不能扣减重新加入后的状态。指定网卡 TCP 贡献同一绑定的负载，UDP 不参与 TCP 性能模型。
- 1 秒采样；成功下行写入计数保留在绑定累计计数中，因此两次采样之间已结束的连接仍贡献吞吐。活跃连接保留 3 秒活动窗口；拨号及建立后 3 秒计入启动负载。样本采用 0.2 EWMA，累计客户端写入耗时超过窗口一半时不学习该窗口。
- 所有候选至少有 3 个有效且 30 秒内更新的样本时，以 `近期聚合转发速率 / (当前传输负载 + 1)` 排序，10% 内差异按最近选择时间打破平局。否则使用预留及活跃负载均衡。
- 每 20 次自由 TCP 分配尝试探索最久未分配的合法链路，同一链路的探索间隔至少 5 秒；无可探索对象时采用普通评分。不创造额外连接、不限制已建立连接的流量。
- Core 遥测输出 `legacy` / `learning` / `observing`、分配原因计数与各卡样本年龄；`observing` 只表示有足够近期样本，不表示模型最优。

当前算法是基于观测服务速率的负载分配基线，**不是后文的边际收益/容量模型**。尚无目的上下文模型、地址族独立模型、共享瓶颈推断、失败率连续评分、短请求分类、分配配额渐变、CDN 与网卡协同实验。CDN 流量被计入观测，但不作因果归因。后台采样仍在性能锁内扫描 lease；选卡本身只扫描候选网卡，需通过高连接数基准评估采样锁等待后再决定是否拆分采样锁。

实验版不能宣称比轮询普遍更快；尤其应用需求变化、混合来源或样本陈旧时可能回到负载均衡。只有后文真实对照验收通过，才考虑升级默认。

## 1. 产品目标与发布边界

将新连接的均匀分配升级为反馈驱动的自适应分配：在路由和健康约束下，提高 TCP 下载的持续聚合吞吐，并降低固定工作量的完成时间。首版不承诺上传优化、UDP 优化、单连接跨网卡、现有连接迁移或全局最优。

实验版新增「自适应速度（实验）」；现有最大速度模式暂时保持轮询。通过真实网络验收后，将自适应模式命名为「最大速度优先」，轮询保留为高级选项。不能在旧配置加载时悄悄切换算法。界面显示实际执行策略与回退原因。

## 3. 决策模型

### 3.1 观测与身份

性能管理器由 Server 持有，供聚合和指定网卡通道共享负载信息。指定通道只提供负载观测，不能成为自由选卡的实验样本。归属未知的 direct 流量不强行归因。

绑定身份包含网卡名称、接口索引、IPv4/IPv6 源地址与单调递增代次；网络绑定改变时创建新身份。连接持有原身份直到结束。目的上下文使用已有可信域名和端口；无域名时使用目标 IP 和端口。地址族未解析时标为 unknown，成功后记录实际地址族，不在选卡前虚构结果。

每个连接记录累计上下行字节、最近传输时间、客户端写入耗时、拨号阶段及结果。控制器每秒读取计数差值；连接结束事件保存尚未采样的差值，防止短连接消失造成漏计。成功写给客户端的字节是调度代理指标，不等同于文件有效字节。

每张卡记录：近期聚合下载速率、传输活跃度、启动负载、待拨号预留、建连失败率、样本年龄、波动和可信度。客户端持续阻塞或应用需求不足的样本只能描述当前业务吞吐，不能据此下调容量估计。

### 3.2 分两阶段学习

首版使用可解释的容量/单流模型，第二阶段才启用实测并发桶。不要在没有足够观测时同时拟合目的容量、共享瓶颈损失和并发曲线。

首版对每张卡 i 估计可用容量 C_i，对目的上下文 c 估计同类单流速率 r_i,c。C_i 只有在持续有需求、无明显客户端背压且增加并发后吞吐出现平台时才标为可信；否则为 unknown。短时峰值不定义 C_i。r 使用近期传输窗口的稳健平滑值；源站限速也是目的上下文性能的一部分。

给定当前所有上下文的预计需求 D_i：

```text
D_i = 各活跃/启动连接的预计需求之和 + 各拨号预留的预计需求之和
G_i = min(C_i, D_i + r_i,c) - min(C_i, D_i)
S_i = (1 - p_fail_i,c) × G_i
```

单位统一为字节/秒。未知容量不填零、不填无穷；该候选进入低置信度路径。空闲连接权重为零，短暂断流的活跃度平滑衰减。连接同一时刻只能处于 pending、starting、active、idle 中一个状态，避免重复计数。

这是局部排序近似，不能解释为确定的因果增益。共享出口、混合目的变化、CDN 切换或背压明显时降低可信度，不计算没有依据的固定损失罚分。

第二阶段使用近期相同背景负载下的并发桶，替换 G 的局部预测；允许拥塞造成负增益。只用可比较窗口，缺少相邻并发数据时回退首版模型，不跨很久的历史相减。各目的必须共享网卡总负载预算。

### 3.3 选择顺序

1. 应用显式路由、地址族、重试排除与现有健康候选规则。
2. 零候选返回现有错误；单候选直接选择但仍登记负载。
3. weighted / round-robin 调用原算法。adaptive-throughput 的 UDP 走轮询。
4. TCP 候选满足探索预算时，选择最久未观察且没有未决探索的合法链路。
5. 其余候选按收益可信度比较；只有预测差异超过观测噪声时采用收益优先。
6. 预测不可区分或数据不足时，按 pending + starting + 平滑活跃度较少者选择，再稳定轮转。不是按所有存活连接数。
7. 在同一临界区预留负载，返回 lease。

收益全为零或负数时，选择预计损失较小、负载较低的合法链路，仍接收业务。已知短请求上下文采用建连耗时/失败率排序；未知请求不能假设为下载，也不能读取 HTTPS 内容预测剩余大小。

### 3.4 探索与稳定性

冷启动对每条健康候选进行有限自然连接探索。稳定期使用确定性令牌预算：初始实验值每 20 次自由 TCP 分配累积一个探索令牌，最多保留一个；候选间按样本年龄轮转。每张卡最多一个未决探索。探索窗口到期后结束实验标记，已有连接继续正常传输和计入负载，不长期占用实验槽位。

5% 仅是新连接数目标，绝不是探索字节或耗时上限；一次探索可能成为长连接。恢复探测和性能探索分开，不能绕过 health 候选过滤。自然连接太少时显示样本不足，不生成额外业务流量。

控制器初始每 5 秒更新偏好。收益差别必须持续两个有效窗口才能改变主要偏好；明确连接故障由健康机制立即处理。旧样本随年龄降低可信度。偏好变化通过分配配额限制，初始每窗口最多调整 10 个百分点；低请求率下不积攒补发额度。全部参数是实验起点，须由压测决定。

Steam CDN 探索标记和调度探索标记必须关联；同一上下文避免同时启动两种探索。不可避免的外部端点变化只保存吞吐观测，不用于判断选卡增益。总吞吐没有改善时降低进一步倾斜，不能凭一次下降自动认定某卡有害。

## 4. 并发、接口与生命周期

建议拆为 `performance.go`（观测）、`adaptive.go`（后台模型）、`lease.go`（负载生命周期）。如下为目标接口草案，不是现有 API：

```go
Acquire(SelectionContext) (Adapter, *Lease, error)
lease.Attach(connectionID, resolvedFamily)
lease.Fail(reason)
lease.Finish()
```

lease 状态：pending → starting → active/idle → finished；DNS/拨号失败为 pending → finished。Fail/Finish 幂等；Attach 与取消并发时只允许一个终态获胜。拨号成功但 Attach 失败时关闭未交付的 socket 并释放预留。已有连接结束不得扣减新代次状态。

锁顺序与当前 scheduler → health 保持一致。选择锁内仅筛选、读不可变预测快照、比较候选与写预留，不做 DNS、拨号、连接扫描或模型计算。热路径 O(候选网卡数)。后台以短锁复制连接引用，在锁外读取原子计数；结束队列溢出时累计丢失样本并降低可信度，不能阻塞转发或默默当成零流量。

控制器使用注入时钟与单调时间差，支持确定性测试。停止时先禁止新 Acquire，再取消采样、结束预留和释放状态。模型数据首版仅保存在内存，不持久化目的历史。

## 5. 配置、兼容与回滚

增加 `strategy`：`round-robin`、`weighted`、`adaptive-throughput`。字段缺失时 weighted=true 映射 weighted，false 映射 round-robin；未知非空值拒绝。显式 strategy 为权威，返回配置中的 weighted 规范为 strategy==weighted，防止冲突状态传播。

hello 新增 `scheduling_strategies` 数组。旧 Core 缺失该字段时仅认为支持两种旧策略；新桌面不得向旧 Core 发送 adaptive 并接受其静默忽略。已保存自适应但连接旧 Core 时提示核心不支持并阻止该策略启动，用户可选择轮询；不能显示自适应而实际执行轮询。

`SchedulingConfig`、start 参数、Settings、EngineStatus 和前端服务调用全部携带 strategy。兼容旧 SaveSelection 调用时只映射到旧策略，不根据 weighted=false 猜测 adaptive。重新生成项目现用的前端绑定，不手工修改生成输出。

运行时沿用 lifecycle gate 和 commitScheduling：验证 → 安装必要绑定 → 发布配置 → 持久化；持久化失败发回完整 previous。回滚恢复策略和网卡绑定配置，但不重置或复制已有连接的负载计数。模型在相同绑定身份下可以保留，失效预测重新学习。回滚失败时同步 Core 实际状态并明确报错。

## 6. 诊断与资源预算

遥测返回 requested_strategy、effective_tcp_strategy、effective_udp_strategy、状态（learning/stable/insufficient-data）、样本年龄、每卡吞吐/负载/预留/可信度，以及选择原因计数（gain/explore/load-fallback/health-only）。不展示未经证实的“提速百分比”或“已跑满”。

上下文初始上限为整个 Server 4096 项，非活跃项 TTL 10 分钟；已淘汰上下文的活跃连接归入网卡级统计，不能悬空引用。日志只记录采样决策和汇总，不逐包记录域名。发布前测 2/4/8 卡、100/1000/10000 连接下的 CPU、内存和锁竞争，预算按实测基线制定。

## 8. 验证清单

确定性测试：冷启动、模型未知、陈旧样本、收益近似相等、收益全零、探索不饥饿、并发 Acquire 分散、DNS 失败、拨号取消、Attach/Finish 竞态、重复 Finish、来源 IP 改变、删卡后旧连接结束、停止重启、指定通道贡献负载、UDP 行为、健康恢复路径。

协议/事务测试：旧 boolean fixture、新枚举、未知枚举、hello 无新字段、显式策略规范化、两种模式启动、保存失败回滚及回滚失败、Core 重连后状态显示。沿用现有 contract 和 scheduling 测试体系；在支持环境运行 Go race 检查。

性能对照采用独立限速服务器及校验文件，不以模型预测充当实际吞吐。比较轮询、合理手动权重、最佳单卡、自适应；随机化顺序，多次重复并报告置信区间。包含持续补充连接和固定批次任务，避免仅看稳态而忽略慢链路尾部。

场景：100/100、100/20、100/5 Mbps；1/2/8/32 并发；容量下降与恢复；同出口共享限速；源站单流限速；不同 CDN；高延迟；客户端背压；长期连接不更替；IPv6 差异；TCP/UDP 混合。控制文件、下载源、CDN 配置、连接池复用和缓存。

验收记录：有效文件吞吐、完整任务及尾部耗时、建连 p95、失败率、自然连接更替下的收敛时间、探索连接和字节占比、CPU/内存/调度开销。暂定门槛：主要非对称场景收益置信区间下界大于零；对称和单卡场景无超过 5% 的稳定吞吐回退；连接、路由和回滚正确性全部通过。短请求延迟和资源开销门槛在 A 阶段获得基线后固定，不能事后挑选。

## 9. 首版主动舍弃的复杂度

不引入神经网络或在线强化学习，不推断加密请求剩余大小，不重放请求或强制断连，不直接照搬 MPTCP 拥塞控制，不同时上线共享瓶颈分类器。先验证采样质量和简单反馈是否产生实际收益，再决定增加模型复杂度。
