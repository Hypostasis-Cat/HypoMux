# Windows 安装流程修复验证（2026-10-06）

> 本文保留阶段性调查记录；最终实现和验证状态见 [安装事务验收](installer-transactions-2026-10-06.md)。


## 问题与证据

v2.7.0 首次安装用户遇到“旧版 HypoMux Core 文件暂时无法更新”，安装详情为空。
用户诊断报告没有发现安装注册项、Core 服务、HypoMux 进程或默认目录中的安装文件；
32/64 位 Windows PowerShell 的四种环境探针均成功。
报告不包含实际安装器的子进程退出码，因此不能认定某一种环境故障就是该用户的根因。

代码确认，原安装器即使没有旧文件，也无条件启动旧 Core 检查脚本，
并把所有非零返回值（包括脚本异常和启动失败）统一描述为旧文件无法更新。
它只打印子进程输出，没有输出退出码；空输出时缺少定位信息。

## 修改

- 由 NSIS 先检查旧文件是否存在；不存在时不提取、不启动 Core 检查脚本。
- UI 关闭检查也要求已知安装路径存在桌面程序，避免全新安装依赖旧程序清理命令。
- 覆盖安装仍检查当前路径、更换目录时的旧路径，以及 ProgramData 中独立的服务程序。
- Core 的只读属性单独处理，保留其他属性和文件内容，不放宽 ACL；真实写入占用继续阻止安装。
- 文件检查失败保留 HRESULT，不再把全部访问错误描述为文件占用。
- Core 检查失败在对话框显示返回值、目标和报告路径，并将信息保存为 UTF-16 临时报告。
  子进程没有任何输出时仍有退出码；无法保存报告时明确提示。
- Core/UI 检查失败时，静默安装分别返回 67/68，不显示重试对话框。
- 服务查询只有 1060 才按未安装处理；其他错误停止更新。
- 服务停止增加子进程超时；强制结束后限时等待服务停止，替代固定一秒等待及单次 CIM 查询。
- 修正旧 NSIS 卸载注册命令被重复加引号的问题，保留注册命令原有引号。
- 增加可覆盖的构建输出路径，验证构建无需覆盖本地已有安装包。

## 验证

在 Windows 上使用 NSIS 3.12 和 Windows PowerShell 5.1 验证：

```powershell
$env:MAKENSIS = '<repository>\.tools\NSIS\makensis.exe'
go -C desktop test . -run 'TestInstaller|TestMachineInstaller|TestLegacyRecovery|TestVersionMetadata' -count=1 -v
```

新增测试编译和运行生产 NSIS 函数，覆盖缺失文件、残留注册目录、当前目录升级、
迁移目录、独立服务文件、三个文件位置并存、无输出失败、静默安装退出及 Unicode 路径。
另用真实 Windows 文件句柄验证普通文件、只读文件、允许共享写入的读者和真实写锁；
所有情况下确认文件内容未被改写。原有安装目录解析和安装流程检查继续运行。
旧卸载命令引号测试运行一个无副作用的子程序，不操作真实卸载注册项。

完整 `project.nsi` 编译检查使用 `/WX`，将警告作为错误处理。
验证生成的 `.cache/installer-validation.exe` 使用本地现有载荷，仅用于构建检查，
不是已签名的发布安装包，不应作为 v2.7.0 官方补丁分发。

## 尚未覆盖

没有在报告用户电脑上复现原安装器失败；也没有运行会修改本机服务、网络和安装目录的完整安装。
生产发布仍需使用一致版本的正式载荷重新构建、签名，并在干净 Windows 和已有版本环境验收。
现有已发布的 v2.7.0 安装包不会因源码修改而自动改变。
