# Steam 持续评估、有限试用与分阶段短测

日期：2026-09-12。状态：本地实现与模拟回归完成，真实效果待测试。

后续实测与发布前修复见 [Steam 发布前收尾](steam-release-readiness.md)：增加 32 个候选的发现池、按网卡过滤后限额验证，区分客户端中断和节点故障，并补齐构建提交号。

## 实测依据

9 月 11 日 12:40–12:44 的日志记录 114 条识别连接、10 次切换及约 588 MiB 切换传输，占 Steam 归因流量约 6.9%。没有记录到优先候选。部分候选持续低速，其他候选因并发负载改变、基准不足或过期未能晋升。单轮记录不能证明开启优选的净收益。

参考 UsbEAm 作者公开的分阶段校验、测速及多个优选 IP 思路，以及 DepotDownloader 的候选资格筛选和失败反馈。本轮为独立实现，没有复制第三方节点数据库或源码；新增有限短测，预算与真实下载分开。

## 本轮行为

1. 启用期间每五秒评估候选，不依赖新连接或界面轮询。新连接仍可触发同一窗口评估，但同窗口不重复累计优势。重置与关闭取消旧定时器，generation 检查拒绝旧定时器回写。
2. 每个节点最多保留八组精确并发数的样本，超限淘汰最旧组。负载切换保留历史组，恢复时只复用十秒内的新鲜数据；优势确认重新开始，不跨负载直接延续晋升。
3. 候选与原节点当前并发不同，可以取原节点对应负载的近期历史组比较。没有新鲜可比基准时保持有限试用，不用乘除并发数推算带宽。仍要求至少五个样本、8 MiB、两个连续窗口超过基准 15% 才晋升。
4. 每网卡、域名、端口最多两条非优先候选的试用连接，包括正在拨号的预留、已过验证期但尚未结束的试用。优先候选仍最多四条连接；失去优先资格的已有连接计入试用额度，超额时停止新试用，不强断连接。
5. 慢候选需要至少五个有效样本，持续四个相邻窗口、至少十五秒低于相同负载的新鲜原节点基准 25%，才进入一分钟性能冷却。冷却禁止新增选用，不终止已有流量；恢复后清空该候选评分历史，重新有限试用。
6. 沿用客户端写入阻塞过滤；无新样本不累计慢窗口，超过两秒的采样间隔也不触发性能冷却，以减少请求间隔误判。这是保守启发式，不能完全识别应用暂停、磁盘因素或证明 CDN 本身故障。
7. 界面区分持续低速冷却、单候选并发限制和网卡/域名试用总额度。转发统计、总开关和现有日志入口保持兼容。

## 下一阶段：短测与候选轮换

1. 真实 HTTP 下载提供原响应前缀后，先执行最多 4 KiB 内容验证。合格候选才可进入短测；对象不足 64 KiB 时跳过短测。短测复用当前允许的 URI 和签名，绑定原下载网卡，不携带 Cookie/Authorization，不跟随重定向，不跨域复用签名。
2. 每个发现任务最多短测两个节点，每节点一分钟内最多一次；每次读取最多 256 KiB（另读一字节检查超长），请求限时 1.5 秒，仍受发现任务总计 20 秒和两个后台任务的限制。全局每分钟最多预留 4 MiB 响应体、16 次请求，失败也消耗预算；重置和开关不刷新预算。既有 256 KiB/分钟的小样本校验预算独立保留。预算是应用层响应体读取上限，HTTP 报头、连接及协议开销另计。
3. 严格校验 206 范围、对象总长度、响应体长度和原响应前缀。短测速率包括建连与首字节等待，只是有限请求的参考表现；它不进入实际下载流量或样本数，不直接晋升、不按单次短测淘汰慢节点。首次或复核发现前缀不一致时撤销已有候选资格，原路保留。
4. 在同样试用次数的候选之间优先试用一分钟内短测表现较好的节点；未试用候选优先于已试用候选，避免长期饥饿。多个优胜候选仍由真实流量持续评估，没有直接扩大试用连接上限。
5. 对每网卡/地址族 DNS 返回列表以及会话公共地址按 30 秒时间窗轮换起点，再交错合并，单次仍最多八个候选。来源继续限定精确域名/端口、公共地址和有效 TTL；轮换不延长缓存有效期。扩展的是现有来源的覆盖范围，没有接入需要账号的目录或第三方 IP 数据库。
6. 诊断展示短测阶段计数、响应体预留预算和过期参考速率，和实际切换吞吐分开。内容校验失效条目显示候选不可用；已经占用试用连接的零样本条目显示正在试用。
7. 周期运行与停止前的 Steam 日志补齐实际 Core 握手版本、提交号及配置模式，修正此前这些日志缺少版本归属、可用性默认为 false 的问题。

HTTPS 保持同域名 DNS/会话候选和 TLS 证书校验；无法取得加密下载的真实 URI/内容前缀，因此不套用 HTTP 短测。HTTP/2、QUIC、未知签名和跨 CDN 主机替换仍保持原有边界。全球网络与纯 IPv6/NAT64 的实机效果不能由本轮模拟回归代替。

## 验证

- 核心 `go test ./... -count=1` 和 `go vet ./...` 通过，包含当前工作区其他 DNS/健康检查性能改动；不代表那些修改由本轮实现。
- Steam 专项覆盖无新连接晋升、过期降级、旧 generation、负载组恢复与容量、匹配历史基准、持续慢/暂停/请求间隔/负载不匹配/旧基准、冷却恢复、预留额度和跨网卡隔离。
- 本机 IPv6 回环限制沿用已有环境检查；没有进行真实 IPv6/NAT64 验收或真实 Steam 下载。本轮没有运行 race 检测。
- 桌面 Go 全量测试与 vet、前端 25 文件 / 107 项回归及 `tsc --noEmit` 通过，`git diff --check` 通过。
- 短测专项覆盖预算并发与重置、分阶段准入、首次/复核前缀不一致、重定向、截断/超长响应、短内容跳过、取消及旧 generation、单任务两个节点限制、轮换复测和过期排序。测试使用本地 HTTP 模拟服务，不访问真实 Steam CDN。

## 实机验收重点

固定游戏、下载地区与双网卡，用关闭→开启→关闭的稳定下载窗口比较平均吞吐及失败率。观察优先候选是否有连续可比优势、慢候选是否停止接收新连接，以及降级后是否维持总试用额度。不能把切换次数增多、晋升出现或单张峰值截图作为提速结论。

已在传输的慢连接仍可能存活较久。自动终止并重试属于后续独立设计，本轮不承诺消除这些长连接的拖尾。
