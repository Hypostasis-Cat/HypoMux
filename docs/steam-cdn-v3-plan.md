# Steam CDN 第三版优化方案

状态：第三版已实现，下面保留设计依据；实际边界与实现差异见文末。以 a7b1d8e 的代码和 2026-09-09 13:29–13:39 用户测试为依据。

## 1. 结论与目标

本次运行识别 587 条连接，节点替换 0 次，诊断只有 recognized/http_wait_chunk。
Steam 日志出现 xz.pphimalayanrt.com 向 xz.sycontroller.com 的签名 URL 重定向。
这些证据证明当前下载请求准入没有通过，尚不能判断候选质量或优选提速幅度。
现有日志没有记录具体拒绝条件，不能断言全部请求都因签名参数而失败。

代码还存在两个结构性限制：
- prepareSteamCDN 只在连接开始执行一次。HTTP 首请求不符合条件时，后续复用连接的内容块请求不会再次触发发现。
- 多条连接的样本混入一个 EWMA；该值既不是节点总吞吐，也不能消除并发数量和客户端阻塞的影响。

第三版先保证真实下载进入评估流程，明确每一步结果，然后改善节点选择。保留一个总开关，默认关闭。用户自行验证真实效果。

## 2. 总体流程与边界

HTTP 代理、SOCKS 域名、TUN 的 SOCKS IP 入口共用：

识别下载域名 → 观察请求/响应 → 分类请求 → 收集候选 → 按网卡验证 → 新连接小比例试用 → 评估收益/失败 → 保留或冷却。

- 保留原有网卡调度、绑定和直连旁路规则。
- 原有 TCP 连接不迁移；复用连接中的后续请求只供发现和采样，候选选择作用于以后新建的连接。
- TLS 继续端到端加密，仅使用现有可见 SNI 与证书验证。TLS 内部的签名 URL、HTTP/2 流及重定向不可见时明确标记能力边界，不安装证书或解密。
- HTTP/2 明文升级、无法可靠解析的消息等先透传，不强行套用 HTTP/1.1 解析。
- 关闭立即取消探测、清除签名材料、停止新增探索；现有连接继续完成。重新评估保留一份脱敏诊断快照再清空学习结果。

## 3. 第一步：把等待原因拆清楚

以结构化判定结果替代空字符串：Eligible、Reason、MethodClass、PathClass、QueryProfile、HeaderComplete。

原因至少包括：
- 未识别到域名 / 域名不在范围 / 本地地址旁路；
- 请求头不完整、超出上限、解析失败、协议不支持；
- 首请求是 HEAD、鉴权/元数据请求、不是内容块路径；
- 带 Cookie/Authorization、带请求体、未知查询参数组合；
- 签名请求可评估、签名已失效/被拒绝；
- 等待原节点响应样本、候选 DNS 不可用、范围请求不支持；
- 候选内容不同、候选连接失败、探测预算用尽、只有原节点。

分别累计连接数、HTTP 请求数、可评估请求数、候选验证数、试用连接数、实际产生下载数据的试用连接数。
不将重复状态快照计入事件次数。近期详情为有界事件列表，计数不依赖列表是否已轮转。

日志仅记录枚举分类、状态码、域名、网卡、IP、计数及耗时，不记录完整 URL、任意查询参数名/值、Cookie、Authorization 或响应内容。错误消息也需经过结构化映射，避免 HTTP 库错误把 URL 带入日志。

## 4. 第二步：观察复用连接

在已识别、受支持的 HTTP 下载连接上增加双向观察器。实际转发字节保持原样，观察器只旁路解析，不重新序列化应用请求。

- 支持 HTTP/1.1 请求/响应关联、Content-Length、chunked 编码、无正文响应和正常持久连接。
- 首个请求是鉴权/元数据请求时，继续等待同一连接的后续内容块请求。
- 按内容长度跳过正文，不在二进制正文中搜索 GET 或 HTTP 标记。
- 对流水线请求维护有界 FIFO；正确处理 HEAD、1xx、连接关闭分隔响应、Upgrade。
- 解析歧义、过大报头、队列超限等触发观察器退出，保留所有已读字节并继续原转发，不使整条下载失败。
- 候选异步探测不阻塞正常转发；内存和队列满时丢弃诊断机会而不是阻塞数据。

初始设计限额：每方向报头 16 KiB，单连接待关联请求 16 个，最多观察 64 条下载连接。具体内存上限通过测试计量；不缓存完整游戏块。

## 5. 第三步：签名 URL 与重定向

### 签名请求

将普通公开块与签名块分开处理，不能直接删除 RawQuery 判断后全部放行。

- 仅允许精确下载域名、内容块路径和已定义参数组合；未知组合继续原连接，并显示具体原因。
- 从本次真实请求取得原始 Request-URI，保持转义、查询参数顺序和值，不解析后重新拼接签名 URL。
- Cookie、Authorization、请求体仍不参与主动探测；单次令牌语义不明的类型不重放。
- 允许探测的签名材料只在当前任务内存保存，初始最长 30 秒；取消、完成或明确拒绝后立即丢弃引用，不写磁盘、遥测或错误文本。
- 签名验证按真实请求所属网卡进行，不把一张网卡取得的签名广播给另一张网卡。其他网卡等待其自身真实请求样本。
- 原节点参考样本优先从本次成功的真实响应旁路取得，减少再次请求原节点及一次性签名失效风险。
- 对候选只在相同 scheme/host/port 下改变连接 IP，绑定原网卡，保留 Host 和原签名。
- 401/403 或签名疑似过期先归因于该探测材料失效，不直接给候选记“低速”；不得无限重试。
- 范围响应暂维持严格 206 校验，并支持 min(4096, 已知块长度) 的短块前缀。比较响应范围、总长度和前缀；前缀相同不等于整块一致。
- 服务端不支持 Range 时显示“不支持小样本校验”，不自动改成大文件测速。

### 重定向

优先观察原节点真实响应的 Location，验证目标关系，但仍让 Steam 自己执行跳转。

- 已观察到的 xz.sycontroller.com 可作为首批精确适配域名；从该域名自己的真实请求获取签名，不复制来源域名的参数。
- 不把 HTTP 302 当作节点内容验证成功，不让主动探测客户端自动跨域跟随重定向。
- 不因任意第三方 302 自动信任整个域名后缀；未知目标只记录脱敏域名及“不支持的重定向目标”。
- 明文 IP 重定向没有可用同域名候选时保持原路，不能把该 IP 擅自用于其他域名。
- 若确需后续扩展域名，应根据脱敏诊断与兼容测试逐个增加规则。

## 6. 第四步：候选来源、排名与回退

节点身份分离：ObservedOriginal（原连接观察到）、Validated（同网卡同域名验证通过）、Trial（正在试用）、Preferred（样本支持优先）、CoolingDown。

原节点有吞吐数据不等于可替换其他原节点；只有验证通过的节点才能作为替代目标。
候选继续来自同域名各网卡的 DNS 记录；各网卡独立验证，不跨主机混用 IP。

统计分离：
- 节点总吞吐：统一时间窗内该网卡、域名、IP 的下行字节增量求和 / 窗口时长。
- 当前连接数：同一统计维度活跃连接数。
- 选择评分：结合单连接有效样本分布、并发负载、连接失败及冷却；不能直接按总吞吐选，因为连接多会自然推高总量。
- 客户端写入阻塞耗时单独记录。长时间客户端背压或无有效数据时不据此降级节点，不标记为“磁盘瓶颈已确认”。
- 展示最近窗口而非旧连接尾部样本；无活跃下载时显示空闲，不继续显示陈旧低速。

初始调度参数是待验证的设计值，不是实测最优值：
- 首批仅让最多 1/8 新连接试用候选；同网卡每候选最多 1 条并发试用连接。
- 至少 3 条有效连接、累计 8 MiB，并有可比负载下的原节点样本，再考虑偏好升级。
- 连续两个观察窗口优于原节点约 15% 才升级，减少小幅波动导致的来回切换。
- 原节点样本不足时显示“证据不足”，不宣称已经获得收益。
- 候选建连失败继续使用保留的原连接，候选冷却 60 秒；全部不可用时自然保持原路。
- 应用数据已发送后发生失败，不能透明迁移当前 TCP 流。降低后续新连接的选择优先级，由 Steam 按其逻辑重试。

探测仍最多 2 个后台任务、每任务最多 20 秒、最多 8 个候选；再加全局响应体预算（建议 256 KiB/分钟）和连接尝试频率限制。预算耗尽显示暂停原因，等待后续任务。
不主动扩大 Steam 下载并发，不把同一块复制下载来制造聚合速度。

## 7. 界面

保留单个“Steam 下载节点优选”开关，技术规则不做成一排需要用户理解的开关。

主状态区显示当前最关键状态：未识别流量 → 已识别但请求暂不支持 → 正在验证 → 仅原节点可用 → 候选试用中 → 已有有效候选传输。
“已优选连接”拆成“已切换连接”和“已产生下载数据的切换连接”，避免只连通未下载就宣称优化成功。

节点表：网卡 / 域名 / IP / 来源与验证状态 / 当前总吞吐 / 活跃连接 / 有效样本 / 最近失败原因。
高级详情折叠显示：请求分类统计、验证失败分类、签名或重定向支持状态、预算及冷却。
不要根据网络速率下降自动断言磁盘瓶颈；可提示用户对照 Steam 磁盘活动。

## 8. 验证与交付顺序

同一轮代码交付分四个可检查步骤：
1. 请求分类与节点身份、统计模型，修正误导性的状态。
2. HTTP/1.1 复用连接观察器和无损回退。
3. 签名请求及精确重定向目标适配，再接入候选试用。
4. 模拟网络回归、前端检查、构建完整安装包，交用户验证。

测试夹具不得使用用户日志中的真实令牌。使用虚构的同结构签名 URL，覆盖：
- 两种代理模式与 SOCKS 域名入口；首请求非块、第二请求为块；多个复用请求。
- 任意分包边界、短块、chunked、HEAD/1xx、流水线、EOF、超限、升级与透传字节一致。
- 原始签名字节保留；未知查询组合、Cookie/Authorization 排除；重定向不跨域带令牌。
- IP/网卡绑定签名拒绝、过期、401/403、Range 不支持、内容不一致。
- 原节点不能未经验证成为替代节点；并发限额、预算、取消、重置与旧任务回写隔离。
- 节点总吞吐求和、空闲清零、背压样本排除、旧核心兼容；日志和错误文本无令牌。

实际验收分两层：
- 功能生效：真实内容块进入 Eligible，验证结果可见，若存在合格候选则产生试用及有效传输。没有候选时要有明确原因；不能把必须发生切换作为所有网络的通过条件。
- 性能收益：固定双网卡与下载区域，关闭/开启各测多段稳定下载，比较下载字节/时间、失败情况和 Steam 磁盘活动；不以单张峰值截图或安装/解压阶段判断收益。

交付继续使用完整安装包同步更新 Core 服务。自动测试只用模拟网络；不替用户启动 Steam、安装测试包或运行真实效果测试。


## 9. 第三版实际落地与明确边界

- 实现采用同步增量旁路解析器，而非异步复制整段流量的队列。没有网络等待；报头受限，正文按 framing 跳过，每连接最多 16 个待关联请求、全局最多 64 个观察器。观察失败后原样透传。
- 已覆盖首请求 POST 元数据、后续 GET 块、HEAD、1xx、流水线、chunked 跳过、任意分包以及超限退出。未知协议、关闭分隔正文无法继续关联时停止观察，不影响转发。
- 主动校验目前只使用真实 200、未压缩、已知正 Content-Length 的响应前缀；chunked 响应仍可观察后续请求，但该响应自身不触发校验，并显示原因。
- 精确支持 xz.pphimalayanrt.com / xz.sycontroller.com 的 auth_key（可带 reqhost），及 st.dl.eccdnx.com / gstore.val.manlaxy.com 的 expiration_time+token。未知参数组合保持原路；这些适配仍需真实服务确认可重用及 Range 兼容性，失败时显示原因。
- 签名 URI 保留原字节，只在原网卡上对同 Host 的 DNS 候选校验，不跨域跟随探测重定向。真实响应的 Location 只用于识别已知目标，客户端自行跳转后再观察其真实请求。
- 请求材料最迟 30 秒清除；部分报头在下一次 5 秒清扫时退出观察；开关取消通过上下文回调关闭观察器。后台探测最多 20 秒，最多 2 个并发；每分钟最多保留预算 256 KiB 响应体和 64 次 HTTP 尝试，重置开关不重置预算。
- 只验证长度一致的最多 4 KiB 前缀；支持短块。完整内容校验仍属于 Steam。基准来自当前真实连接，不额外回放原节点请求。
- 未验证的原节点不会被选作替代。未晋升候选最多接 1/8 新连接、每候选最多 1 条并发试用；新连接数据发送前建连失败可保留原路，发送后不能透明迁移。
- 初步晋升要求 3 条正常完成的有数据连接、8 MiB、原节点至少 3 个样本，以及两个 5 秒观察窗口内更新的样本显示超过 15% 优势；样本超过 10 秒变旧则撤销晋升。晋升候选最多 4 条并发选用，仍受原网卡调度约束。
- 排名仍为经过客户端阻塞过滤的单连接样本 EWMA，并非完整负载归一化模型。不同并发负载会影响比较，晋升仅是保守启发式，不等同于实测收益保证。
- 写入客户端超过 20 ms 的耗时累计；其占样本窗口一半以上时跳过评分。不能据此认定磁盘瓶颈。统一 5 秒字节窗口另用于节点总吞吐显示。
- 界面显示累计可评估请求、原响应样本就绪、候选验证、切换与产生数据的连接、总吞吐和活跃连接。产生至少 64 KiB 转发数据才计入有效切换，但并不代表 Steam 已验证整块成功。

实现文件：steam_observer.go（分类及旁路 framing）、steam_observed_probe.go（原响应基准、预算接入、节点流量及试用）、steam_http_probe.go（有界 HTTP 范围校验）、steam_cdn.go（节点身份及状态），两种代理入口共用。

本次验证：前端 25 文件 / 105 项测试及生产构建通过；桌面 Go 全量测试与 vet 通过；引擎 Go 测试及 vet 通过（排除此前在未修改基线也复现的 TestTUNTCPPoolRelaysLiteralIPv6WithBoundSource、TestSOCKSUDPRelaysLiteralIPv6WithStableFlow 两项本机 IPv6 环境失败）。真实 Steam 效果尚待用户测试。


## 10. 实机反馈后的覆盖与长连接优化

用户报告关闭时约 55 MB/s；第三版实机出现了候选切换及数据传输，但不同时间段的速度不能直接作为净收益结论。
本次增加精确目标 dl1.steam.clngaa.com、gstore-y.bal.manlaxy.com，兼容 t+k（可带 rdkey）、expiration_time+token，以及原 xz 主机的可选 reqaidabccty。保留原始签名字节、原网卡绑定和所有校验限制。未知字段、重复字段、过期的 t/expiration_time 仍拒绝主动探测。

直接 IP 重定向单独标记“交由 Steam 原路下载，没有同域名 DNS 候选”，不再笼统计作未知重定向，也不擅自把该 IP 加入其他主机的候选池。

原晋升门槛依赖 3 条连接正常结束，对持续复用连接会迟迟不生效。现在使用传输过程中的至少 5 个有效评分样本、累计 8 MiB 有效采样字节，以及两个观察窗口的更新样本和 15% 优势；不再要求连接先结束。EffectiveBytes 定义相应改为有效评分样本累计字节，结束时不重复累加。保留 1/8 探索、每候选 1 条试用/晋升后最多 4 条并发、背压过滤、样本过期撤销和失败冷却。

按用户要求仅在本地做代码检查，推送 main 后由 Build Desktop Actions 生成安装包，不在本地打包，不运行真实 Steam 效果测试。

## 11. 工具箱入口与活跃试用晋升

- Steam 下载优选从设置迁移至侧栏「工具箱」，沿用 AppShell 页面切换、侧栏选择指示器、GlassSurface、Fluent 开关与全局动效配置。现有开关持久化键不变，系统代理和 TUN 共用原有后端配置接口。
- 工具卡片集中展示开关、已切换连接、已传输数据、优先候选和回退次数；节点表格独立滚动，诊断默认折叠。后续工具可在同一页面加入独立卡片。
- 将试用并发准入检查移至评分之后，允许尚未结束的试用连接积累两个新鲜优势窗口并晋升。普通候选仍限一个并发试用，优先候选仍限四个；评分不足或过期时保留原路。
- 回归测试覆盖占用试用时晋升、四连接上限、过期降级，以及工具箱开关保存失败时恢复持久化状态。浏览器用模拟遥测检查明暗主题与窄窗口；实际下载效果由用户实机验证。安装包由 GitHub Actions 构建。

## 12. 全球网络与双栈发现

全球策略沿用 Steam 实际请求的下载域名，不根据 UI 语言或国家标签选择服务器，不覆盖用户 DNS。现有 *.steamcontent.com 匹配不限定地区；国内合作 CDN 规则继续生效。未知合作 CDN/未知签名尚未自动纳入，单地址域名没有同域名替代候选，不能宣称所有地区或运营商均有收益。

- 每个有对应源地址的网卡分别查询 A / AAAA；最多四个并发解析调用，整个发现阶段限四秒，每次调用限两秒。
- 候选按网卡和地址族交错合并，上限八个。地址规范化去重，重复地址采用最短有效期；过期、私网、错误地址族答案不进入池。
- 继续在实际承载下载的网卡上验证候选，保留 Host/SNI 与签名原文；HTTP 内容校验和 TLS 证书验证保持原有边界，不做 HTTPS 解密。局域网缓存保持原路。
- UI 使用现有中英文机制，并显示 IPv4 / IPv6。全球合成域名测试仅检验匹配策略，不将测试域名作为实际节点列表。
- 验证覆盖并发解析、多网卡/地址族公平性、纯 IPv6、取消、TTL 与重复地址。实机香港、日本、美国网络效果仍待当地用户测试。
