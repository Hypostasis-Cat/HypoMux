# Steam 下载节点优选

## 目标与开关

在系统代理和 TUN TCP 池内，为同一 Steam 下载域名按实际出站网卡选择 CDN IP。
默认关闭；设置持久化，开启/关闭作用于新连接，现有下载连接不被强制中断。
关闭会取消探测并清空排名；重新评估按钮也清空排名，从随后下载重新学习。
不修改 hosts、系统 DNS、Steam 配置、证书库或游戏文件。

## 数据路径

1. 保留当前路由与网卡调度，直连通道不参与优选，指定网卡仍走指定网卡。
2. HTTP/CONNECT/SOCKS 域名请求直接取得域名；TUN 的 SOCKS IP 请求在原连接建立后，
   有界读取 HTTP Host 或 TLS ClientHello SNI。读取内容原样转发，识别失败用原连接。
3. 仅处理内置 Steam 下载域名及 TCP 80/443。无域名、ECH、QUIC/UDP 保持原流程。
4. 按当前 DNS 策略、绑定各网卡查询同一域名的 A/AAAA 全部记录；合并同域名候选。
   不下载第三方 hosts 列表，不将任意其他 CDN 域名的 IP 强行用于当前域名。
   探测使用独立解析器和取消上下文，不触发主解析器的 DNS 降级事件。
5. 按网卡对候选做有界 TLS 探测，使用原域名 SNI 和系统信任链验证。
   原下载仍自行进行端到端 TLS 验证；探测不读取账号、Cookie 或下载内容。
6. 冷启动先使用原路径；候选通过验证后，用有限的新连接探索候选，以真实转发的
   下行字节/时间学习吞吐，随后偏向已有较好表现的节点。无独立大文件测速流量。
7. 替代连接必须成功才关闭原上游；失败回退原连接，失败候选冷却。

## 约束与状态

- 排名按网卡、精确域名和端口隔离；最多 64 个域名，8 个候选/域名。
- 全局最多 512 条验证记录、2 个探测任务；每任务最多 20 秒，每次 TLS 验证或
  替代连接最多 750 毫秒。识别最多 16 KiB / 300 毫秒。
- 探测有全局并发限制、超时及取消；DNS TTL 和最长 10 分钟共同约束缓存有效期。
- 状态包含网卡、域名、IP、观测吞吐、样本数、选用次数、冷却与失效时间。
- 吞吐是实际连接观测值，包含应用读取速度影响，不等同于线路额定带宽。
- 单个 DNS 结果或原节点表现最佳时可能没有提升；不保证跑满带宽。
- 原目标完全无法连接时，无法进入后续优选阶段，仍沿用现有连接失败行为。
- 局域网地址和本地内容缓存不替换。替代上游建连成功后的应用层错误不能透明重放；
  回退计数仅表示替代上游建连失败后使用原连接，不代表所有应用层错误均可修复。
- 当前选择范围是 DNS 返回的同域名 IP；不跨 CDN 主机改写 URL，不修改 Steam 下载区域。
- 不以低 ping 代替下载速度，不复制 UsbEAm 的节点数据库。

## 交付与验证

引擎：DNS 多地址结果、共用优选器、HTTP/SOCKS/TUN 接入、运行时开关和遥测。
桌面：持久化开关、运行状态、节点列表和重新评估；兼容不支持新能力的旧核心。
协议：增加可选启动字段及能力声明，保持 protocol v1 向后兼容。

自动验证覆盖：默认关闭、热关闭、取消、缓存过期、网卡隔离、候选失败回退、
TLS 验证拒绝、HTTP/SNI 识别、未识别字节原样保留、直连绕过和两种入口。
运行 Go 测试、前端测试与构建；实际双网卡 Steam 下载需在真实网络环境做 A/B：
同一游戏/区域分别比较关闭和开启后的有效吞吐、完成时间及失败率。

## 实现入口

- `engine/internal/proxy/steam_cdn.go`：共用候选池、验证、真实吞吐排名及回退。
- `engine/internal/proxy/steam_sniff.go`：无损 HTTP / TLS SNI 识别，包括分片 ClientHello。
- `engine/internal/server/steam_cdn.go`：`steam_cdn.configure`，运行时启停、清空及状态读取。
- `desktop/internal/services/steam_cdn.go`：持久化与运行时事务、旧 Core 能力检查。
- `desktop/frontend/src/components/SteamCDNPanel.tsx`：状态、节点和重新评估。
- 设置页：Steam 下载节点优选（实验性），默认关闭。
