# Steam 下载优选完善与群测计划

日期：2026-09-11。状态：分阶段路线图；本轮实现与验证见文末，后续计划不代表已经交付。

## 目标与交付约束

将实验功能完善为可解释、可关闭、可验证、适用于不同地区网络的下载节点优化工具。完成不等于每条宽带都提速；原节点已经最好、没有替代节点或协议不支持时，正常沿用原路也是正确结果。

系统代理和 TUN 共享核心逻辑；保留一个总开关、现有配置与工具箱入口。真实效果由用户和群友验证。开发侧完成模拟服务、协议回归、资源开销与 UI 检查，不启动真实 Steam 下载，不本地打包。

用户已于 2026-09-11 授权收尾、提交并推送，由 Actions 生成可追溯到提交号的测试包。工作区 TUN/DNS 修复经核对后独立提交；其他无关目录不纳入本轮。

## 当前基线

已交付：按实际 Steam 域名、用户 DNS、多网卡 A/AAAA 发现候选；HTTP 前缀内容验证、TLS 证书验证；实际流量采样、保守试用与晋升；开关、诊断和工具箱。

本轮新增：独立流量归因、会话候选、失败暂停、最近晋升评估原因，以及活跃节点 DNS 过期后保留统计但撤销新连接候选资格，详见文末。

仍有缺口：更完整的负载归一化、基于对照证据的性能退化检测、未知 CDN 适配材料、全球端到端验收。DNS 候选单元测试不能作为纯 IPv6/NAT64 验收。

## 最新产品调整

用户要求删除「预览群测报告」。不再增加专用报告入口、弹窗、保存 API；群测沿用现有诊断日志。下文原报告条目由结构化日志替代，不再作为待交付功能。

## 第一阶段：诊断与统计闭环（先交群测）

1. 明确节点状态：原路观察、待验证、待试用、试用中、优先采用、冷却、验证过期。区分“评分未通过”和“并发额度已满”，标注评估时间，避免陈旧原因被看作实时决定。
2. 对切换连接单独累计实际下行字节、当前吞吐、活跃连接、连接失败和传输失败。与原路连接分别统计，不能把同 IP 的原路流量计作优化收益。
3. 保持现有总节点吞吐；明确采样有效字节、转发字节与 Steam 完整内容校验是不同概念。不要将 TLS 握手或 HTTP 错误正文等同于内容下载成功。
4. 沿用现有结构化诊断日志记录版本/提交号、模式、开关状态、时间区间、网卡别名、候选来源、阶段计数、切换与原路字节及传输失败。地区/运营商由测试者另行选填。
5. 不增加专用报告入口、预览或导出 API；不记录 URL 查询串、签名、Cookie、Authorization、账号、MAC 或本机完整路径。域名/CDN IP 为诊断项；不自动上传或发送群消息。

验收：同一节点混合原路/切换连接时仍可准确归因；重置/关闭/停止/旧 generation 回写不会串账；并发字节统计不重复；诊断无请求凭据；旧核心缺少字段时界面正常。

## 第二阶段：扩大候选来源

按来源可信度逐层实现，每层都先做独立验证，再接入选择器。

1. 保留当前多网卡 DNS，为每个候选标注来源、发现时间和有效期。
2. 汇集本次会话真实观察到的同域名公共地址。历史观察不是验证，必须在目标网卡按当前内容样本重新验证；严格限定域名、端口和地址族，并设短期上限。
3. 研究 Steam 官方内容服务器目录的可用接口、鉴权、返回语义和地区选择机制；以可核验的一手文档或接口实现为依据。目录只能作为发现信息，不能直接视为可替换地址。
4. 如果目录返回不同域名，单独设计跨域内容兼容验证。首版不把别的主机 IP 填给当前 Host/SNI，不跨主机复用签名，不修改 Steam 下载地区。不能安全验证时保留候选为观察信息。
5. 官方来源不足时，再评估维护合作 CDN 规则清单；确认来源和许可，附版本、有效期与回滚方案。远程规则只能是受限数据，不能携带可执行代码或任意探测 URL。暂不引入未经核验的社区 IP 大表。

验收：每个候选可解释来源；私网/LAN 缓存保持原路；跨网卡必须重新验证；目录不可用不会阻塞下载；来源过期撤销新连接资格；发现、校验和请求材料均有数量/时间/流量上限。

本阶段外部接口研究若证明不可用，明确记录结果；不能为了满足“有全球节点库”而接入不可靠数据。

## 第三阶段：试用、评分与退化控制

1. 将发现、验证、比较、并发准入拆成明确步骤。当前优先级原因只代表最近一次决策，增加时间信息和过期状态。
2. 比较同网卡、同域名、相近时间与并发负载下的有效样本。样本不足显示“暂不能比较”，不计算夸大的百分比。
3. 将短连接、长连接、慢客户端、并发负载变化、停顿分开处理；评估单连接 EWMA 在这些场景的偏差，先用模拟负载证明改进再改变阈值。
4. 保留少量探索，已验证差节点进入有期限冷却；恢复时先有限试用。对切换后的响应拒绝、断流等记录实际失败，不能只统计 TCP 建连失败。
5. 检测连续失败或证据充分的持续退化时暂停为相关网卡/域名选择候选，沿用原路并解释原因。不要只凭 Steam 总速下降判定 CDN 退化；不得自动重放已发送的数据。

验收：慢/拒绝/断流候选可退出；原路始终可用；开关取消不强断已有下载；长连接可晋升、过期可降级；预算和并发限额在重置及高频开关下有效。

## 第四阶段：协议与全球兼容矩阵

- 从脱敏报告识别真实缺口，再补精确域名与签名规则；不扩大通用 CDN 后缀匹配。
- HTTP：验证 Content-Length、Range、重定向、复用、不同分包和截断；chunked 内容采样若落地必须有有界解码与一致性验证，未知格式继续透传。
- HTTPS：保持证书校验，不解密用户连接；加密协议无法取得内容样本时准确展示能力边界。HTTP/2、QUIC 不声称已有内容级优化。
- 网络：IPv4、双栈、纯 IPv6、NAT64 分开验收；逐项核查 DNS 出站源地址、解析传输、连接绑定和恢复，复用或衔接另行进行的 TUN/DNS 修复。
- 生命周期：切换网卡、断网重连、睡眠恢复、DNS 配置变更、Core 重启、开关和重置。

验收：系统代理/TUN 的相同输入产生一致策略；字节透传与回退回归通过；不支持组合明确列出；合成地区域名测试只能证明规则匹配。

## 第五阶段：工具箱交互与交付

页面顺序：总开关与状态 → 切换实际传输数据 → 活跃节点与最近评估 → 折叠诊断。空状态按未启动、等待下载、仅原路、候选不足分别解释。

沿用 GlassSurface、Fluent 控件、既有字体/间距/主题/导航动效；支持中英文、键盘、明暗主题、窄窗口与减少/关闭动画。高频数值更新不引发跳动、自动滚动或抢焦点。

开发验收：相关 Go/前端测试、类型/静态检查、模拟代理协议回归、资源上限测试、界面检查。验收记录区分本次代码、工作区其他修改和环境问题，不把跳过项描述为通过。

## 群测方法

第一轮用现有支持日志收集现状；不必等待所有来源扩展完成。优先招募中国大陆、香港、日本、美国各至少两种独立网络；地区不足的项标记待验收，不以国内测试替代。

每位测试者记录版本、模式、地区/运营商（选填）、网卡组合、Steam 下载地区、是否同一上游宽带。使用同一游戏的大段下载，避免把安装/解压/校验阶段混入对比。

建议每段先稳定约 30 秒，再记录至少 2 分钟；按关闭→开启→关闭顺序，另一轮交换顺序。切换仅影响新连接，暂停/继续不一定更换所有连接，应通过连接统计确认测试条件；做不到则标记混合窗口。尽量重复三组，网络/游戏/下载地区变化时另起一组。

报告平均传输速率、实际字节/时长、波动、切换字节、失败/暂停和 Steam 磁盘活动。峰值截图作为辅助，不能单独证明收益；不要承诺自动排除所有磁盘瓶颈。

功能验收：可识别、可解释、可取消，无候选时下载正常。有候选时能验证并有限试用；未知协议不破坏下载。

效果验收：按网络分别报告改善、持平、退化、数据不足。若两次有效对比都出现开启下降超过 10%，作为优先调查线索而非统计显著结论；出现无法下载、内容错误、持续断流，优先停止该策略并定位。全球稳定版发布需完成代表性网络矩阵和退化问题闭环。

## 实施顺序与完成定义

顺序：第一阶段 → 第二阶段的会话来源 → 第三阶段 → 第四阶段；官方目录研究并入第二阶段，研究结果决定接入范围。每阶段同步第五阶段 UI 和测试，不最后集中补。

开发完成：上述约定能力都有可审查实现与自动验证，未支持场景明确透传；来源与诊断有边界，关闭可用，资源有界，无凭据泄漏。

稳定发布完成：群测矩阵、持续下载和退化修复验收通过。未完成海外/纯 IPv6 验收前继续标为实验性，不宣传覆盖所有全球 CDN 或保证提速。


## 本地开发进展（2026-09-11）

本轮已实现：
- 原路/切换下行字节分别累计，切换活跃连接及五秒吞吐独立统计；总吞吐和归因在同一次加锁、同一个时间桶内更新。数据包含协议开销，不等于校验通过的游戏字节或净收益。
- 按网卡/域名/端口累计切换传输失败，一分钟内三次失败暂停该组候选一分钟；已有传输继续。当前仅失败触发暂停，不根据应用总速推断退化。
- 会话真实公共地址保留两分钟、最多 512 项，限定同域名/端口，与 DNS 候选交错合并。HTTP 仍用当前签名与内容样本在目标网卡验证；HTTPS 也接入会话来源，在每个目标网卡独立验证原域名 TLS 证书，不具备加密内容校验能力。
- 最近评估时间、评分原因、并发准入原因分开展示；不同当前活跃连接数下的样本暂不晋升。此为保守比较门槛，未声称完成全部负载归一化。
- DNS 验证过期后，活跃条目统计保留但撤销新连接资格；重新验证恢复资格，过期且空闲后清理。
- 删除专用群测报告预览和导出；结构化遥测沿用既有日志。工具箱整理为四张指标卡、流量摘要、六列节点表、折叠诊断。来源/地址族放在节点下，原因/时间放在状态下。

研究结论：SteamKit 的 ContentServerDirectoryService 返回 Host/VHost、CellID、AllowedAppIds、代理模板等；CDN Client 接受 CDN 令牌。目录不能无条件转换成其他 Host/SNI 的替代 IP。未接入跨域目录替换、社区 IP 库或用户 Steam 账号。

## 收尾检查（2026-09-11）

- 修正线路暂停诊断被等待样本状态覆盖的问题；暂停期间不展示优先候选，暂停到期后清除陈旧暂停提示。
- 增加 HTTPS 会话候选回归：限定域名/端口、在两个网卡分别进入 TLS 校验、不可信证书不得进入候选池。测试使用本地模拟服务器，不连接真实 CDN。
- 负载变化仍会清空评分样本并重新学习；当前不同节点并发数量不一致时不晋升。这一保守约束可能降低多连接下载的晋升频率，须结合实测诊断再调整，不能仅为提高切换次数放松比较条件。
- 本轮核心和桌面 `go test ./... -count=1`、`go vet ./...` 通过；前端 25 文件 / 106 项测试及 `tsc --noEmit` 通过，`git diff --check` 通过。
- 本机 IPv6 TCP 回环连接被系统拒绝、UDP 回环收包超时，两项转发集成测试明确跳过。竞态检测未运行成功：本机 CGO 关闭且未找到 C 编译器；不将普通测试等同于 race 检查。
- 未进行本地安装包构建或真实 Steam 下载。完整包由推送后的 Build Desktop Actions 生成，实际下载效果由用户验证。
