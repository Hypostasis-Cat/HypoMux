# HypoMux UI 精细化规划

日期：2026-09-23。目标：清透、鲜活、细腻，在纯色背景下也成立。

## 依据与边界

已观察本机 QQ 当前浅色主窗口：导航栏、会话列表、空内容区。大面积中性色、轻微明度分区、局部高彩度图标与提醒、稳定行高和对齐，是本次参考的主要特征。未切换 QQ 主题、未检查其内部实现；无法由截图判断它是否使用特定模糊算法、噪点或原生材质。以下参数均为 HypoMux 提案，不是 QQ 取色或官方规范。

已审阅 HypoMux 桌面端材质、语义颜色、排版、控件、预设与首页相关代码；当前没有运行中的 HypoMux 窗口，因此对现有视觉问题的判断来自代码，需在实施首轮截图中验证。工作区已有其他未提交改动，本次只新增规划文档。

## 核心方向

### 补充观察：用户切换后的 QQ 预设背景

用户随后切换了预设背景，已再次直接观察同一主窗口。上方为淡紫/薰衣草色，左下为较鲜明的嫩绿，中间有浅青过渡，右侧内容区覆盖更浅、颜色更柔和。色块尺度很大、边界平滑，没有明显图案或细碎纹理。颜色在标题栏、导航、列表与内容区域之间保持空间连续，同时各区域有不同的明暗/覆盖程度；这是截图可见的结果，不等于已经确认其透明度、模糊或图层实现。

这次观察补充了“鲜活”的另一种来源：背景本身可以承载较明显的色彩，但应当分布在宽阔、平滑的区域；高信息密度区域保持稳定的文字对比度。先前“少量颜色”的原则适用于控件与信息强调，不能机械地理解为背景必须接近无彩色。

对 HypoMux 的规划因此增加一个与纯色样板同批评审的“柔彩预设”样板：

- 使用一张贯穿窗口的背景色场：上部淡紫、左下薄荷绿、中部浅青，内容侧逐渐变浅。推荐用少量大尺度 CSS 径向渐变模拟；这是建议实现方式，并非 QQ 实现结论。
- 导航适当保留背景颜色；主内容表面提高覆盖率；菜单与输入保证稳定底色。避免所有区域共用一个透明度，也避免给每张卡片各画一份独立渐变。
- 彩度、明度、色块位置、各表面覆盖率组成成套预设，与浅色/深色分别适配。当前浅色配色不能直接罩黑用于深色模式。
- 初始样张可比较导航覆盖率 20–35%、内容表面 65–85%、菜单 94–98%；这些是实验范围，不是从 QQ 测得的数据，实际值随底色及对比度结果调整。
- 第一批交付变为：纯色浅色/深色基线 + 柔彩浅色样板。先确认静态层次，再推广壁纸、深色柔彩与动态效果。

截图中光标附近可见局部蓝色光斑，但来源未经确认，不将其归因于 QQ 主题或作为模仿依据。

先建立独立于壁纸的表面、颜色、排版和交互层级。纯色主题作为质量基线，Mica 与壁纸模式沿用这套层级，再按背景复杂度调整遮罩及面板覆盖率。

QQ 可借鉴的原则是：大面积安静，少量颜色明确；区域之间有微小但稳定的差异；内容排列整齐。HypoMux 是网络工具，首页仍应围绕运行状态、吞吐和网卡调度组织，不照搬聊天软件三栏布局。

## 现有代码中的重点

| 位置 | 已确认的实现 | 优化方向 |
| --- | --- | --- |
| `desktop/frontend/src/theme/material.tokens.css` | 基础面板共享透明度；secondary 以透明度乘数区分；本地/内置背景下 solid 面板清除阴影 | 按表面角色区分底色与边缘，明确纯色背景、实色面板和性能模式的独立含义 |

| `desktop/frontend/src/theme/semantic.tokens.css` | 强调色有 soft/muted/strong，状态色主要为单个颜色 | 为每种语义补齐前景、浅底、边框、强填充及其文字色；分别设计深浅模式 |
| `desktop/frontend/src/app.css` | 网卡行填充为面板透明度的 0.72 倍，选中态主要靠边框与外发光 | 选中行增加稳定浅色底、明确勾选与文字状态，静止时即可辨认 |
| `desktop/frontend/src/app.css` | 卡片有指针边缘光与光晕，首页有模糊装饰光 | 降低常规卡片光晕存在感，主控区域保留少量装饰；先检查 `::after` 的职责冲突 |
| `desktop/frontend/src/theme/design.tokens.css` 与 `typography.tokens.css` | `--hm-density-space` 分别定义为长度与无单位倍率 | 拆分为明确的间距和倍率变量，避免导入顺序使尺寸计算失效 |

注意：移除阴影的规则仅匹配 local/builtin 背景下的 solid 面板，不能据此断言所有纯色主题都没有阴影。

## 视觉方案

### 1. 表面：先把纯色主题做完整

建立四个角色：窗口底、导航底、内容表面、浮层。内容优先通过填充差异和留白分组；分隔线很淡；菜单、弹窗才使用明显抬升阴影。实色面板可保留轻微边缘与接触阴影，性能模式另行减少效果。

浅色候选：窗口 `#F5F7FA`、导航 `#EDF1F6`、内容 `#FFFFFF`、控件 `#F1F4F8`、主文字 `#202632`、次文字 `#5D6879`。深色候选：窗口 `#171A21`、导航 `#1C2029`、内容 `#242A35`、浮层 `#2C3441`、主文字 `#EEF2F8`。

这些只是第一轮视觉样张的起点，需用实际渲染对比度与显示缩放校验。正常内容区不需要强渐变或持续发光。

### 2. 颜色：把“鲜活”放在有意义的位置

保留 HypoMux 蓝的品牌延续性，比较当前 `#1677D2` 与候选 `#1875E5`。按钮、当前导航、选中标记使用清晰蓝色；浅蓝底承载选中区域；成功绿、警告橙、错误红承担状态。

为每种颜色建立 foreground / subtle background / border / solid / on-solid 角色。鲜亮装饰色与白字按钮背景可以分开选择，避免为提高亮度牺牲可读性。上传、下载图表可用蓝与青区分，但必须保留文字/图标标识。

### 3. 首页：强化主次，减少重复容器

视线顺序：运行状态与启动动作 → 当前下载/上传 → 参与调度的网卡 → 次要端口和诊断信息。主控面板可使用极浅蓝底；普通网卡保持中性表面；选中网卡使用浅蓝底和明确勾选。减少卡片内再次套卡片，参数组尽量以间距或细分隔组织。

### 4. 细节：建立一致比例

正文以 13–14px 为基线，辅助文字优先 12px，10–11px 限于非关键短标签。固定中文字体回退并检查中英文混排；速度与统计使用等宽数字，单位降低一级但仍清楚。

圆角初始建议：控件 8px、卡片 12px、浮层 14px。间距使用 4px 基础步长，主要组间距 16/24px。图标使用统一尺寸、笔画和视觉中心；不要通过任意加粗、缩小文字挤压布局。

### 5. 动态与状态

普通 hover 首先改变填充或边缘；pressed 给轻微反馈；selected 在鼠标移开后仍清晰。候选时长：hover/pressed 100–140ms，浮层 160–200ms，页面切换 180–240ms，以实际响应感调整。重要内容不等待装饰动画结束才出现。

保留已有减少动态效果和关闭动画支持，验证键盘焦点、加载、失败、禁用状态；可点击列表行与纯信息卡应有不同的交互反馈。

## 实施顺序与交付

| 阶段 | 工作 | 交付与通过条件 |
| --- | --- | --- |
| P0：基准与变量 | 记录首页、设置页和菜单的当前截图；梳理主题变量与覆盖顺序；拆分密度单位；定义表面/语义角色 | 相同窗口与数据条件的基准截图，变量职责清楚，保留已有主题偏好 |
| P1：纯色首页样板 | 调整导航、主控、速度和网卡选中态；统一按钮、输入、菜单 | 浅色/深色各一套首页；无壁纸、无指针光晕时仍有层次；先以此评审方向 |
| P2：页面推广 | 推广至设置、路由、连接和助手区域；清理重复边框与容器 | 相同控件跨页面一致，信息密度和长文本处理稳定 |
| P3：材质扩展 | 将同一语义层级映射到 Mica、壁纸及性能模式；调整透明度与装饰光 | 亮/暗/复杂背景下文字清楚，性能模式保持色彩与层次，滚动和切页无明显回退 |

优先修改现有 tokens 与共享组件。页面调整应使用角色变量，不继续在页面末尾堆叠主题例外。自定义强调色需要检查 on-accent 对比度，用户已有壁纸及外观设置不应被迁移覆盖。

## 验收矩阵

- 浅色、深色 × 纯色、Mica、明亮壁纸、深色壁纸、复杂壁纸；覆盖低动效/性能模式。
- Windows 100%、125%、150% 缩放；最小支持窗口及常用大窗口；检查细线、字体、图标和裁切。
- 默认、悬停、按下、选中、键盘焦点、禁用、加载和失败状态；状态不能只靠颜色区分。
- 常规文字对比度目标至少 4.5:1，大字和关键控件/状态边界至少 3:1；装饰性分隔线不必强行加深。
- 长网卡名、中英文、极大流量值、多条告警、空列表；数字更新不导致布局跳动。
- 同机比较优化前后的滚动、窗口缩放与页面切换，避免增加全屏模糊或持续高开销动画。

本次为规划阶段，未修改产品样式，未进行应用渲染、性能测试或对比度实测。实施时必须以实际截图与交互验证最终参数。

## 首轮实施记录（2026-09-23）

已实现：纯色表面层级、带蓝灰倾向的深浅色文字与表面、共享控件与菜单底色、网卡选中浅色底、较克制的卡片光晕，以及新增“紫雾薄荷”预设（独立浅色/深色配色，保留原点阵背景）。选择新预设时内容面板默认不透明度为 72%，仍可手动调整。修复了密度变量的长度/倍率冲突，并允许新背景标识经过归一化后保存。

用户明确反馈不喜欢网卡卡片左侧竖线；最终已移除该设计。选中状态依靠勾选、浅色填充与细边框表达，后续迭代沿用这一偏好。

验证：TypeScript 与 Vite 生产构建通过；首页、设置页现有 29 项测试通过；浏览器检查了浅色/深色纯色、浅色/深色柔彩、下拉菜单及 960×680 小窗口；检查时无页面横向溢出，新预设刷新后保留。浏览器设置页因缺少桌面后端显示读取失败，这与主题预览分开记录。本轮未重新打包或安装 Windows 桌面程序，原生 Mica、真实壁纸、多 DPI 与运行期性能仍需桌面端验证。


## 第二轮：首页比例与白色基线

根据用户反馈，纯色浅色（默认背景 + 实色窗口）改为 #FFFFFF 页面与主控表面，导航和次级表面使用中性浅灰；取消主控的强调色染色，选中网卡只保留 4% 强调色填充。此调整独立于柔彩及用户自选背景。

首页将状态与调度摘要整合到主控标题行；移除固定最大高度，允许长文本自然撑开。网卡速度区域默认透明，速度数字 14px、辅助信息 12px；自动调度说明不再为缺失的权重输入框预留空列。状态栏随内容排列，多网卡时中间列表独立滚动。保留无左侧竖线的卡片设计。

验证：生产构建通过；首页与网卡组件现有 20 项测试通过。浏览器检查白色/深色、1280×800 与 960×680，以及八网卡/运行中流量样例。小窗口多网卡列表可滚动、状态栏位于可见窗口内，无页面横向溢出。Windows 原生程序与多 DPI 验证仍未执行。


## 第三轮：设置、路由与连接页一致性

设置项标题 13px、说明 12px，调整行距与控件换行；大窗口背景预设四列、小窗口两列，实色模式的默认预览使用实际主题底色。设置分区导航在默认实色主题下采用不透明表面，避免滚动内容透出。

路由与连接页统一标题尺度和表头可读性，路由固定表头使用稳定实色与轻阴影；连接主数据 13px、辅助信息 12px，摘要允许换行，移除连接行悬停的横向位移。

验证：生产构建及设置/路由/连接共 34 项现有测试通过。检查了 1280×800 设置四列、960×680 设置两列与深色模式、60 条路由样例以及连接空状态。检查页面无横向溢出。连接页浏览器预览无法读取真实桌面后端，含实时数据的视觉验收与 Windows 多 DPI 仍待桌面端完成。
